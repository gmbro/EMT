# 누적 통역 개편 검증 기록

2026-10-30. 기획서 meeting-transcript-redesign-2026-10-29.md를 바탕으로 구현.

## 반영 내용
- 영어 원문 아래 한국어가 붙는 누적 기록. 공급자의 여러 문장 청크는 문장별 ID로 분리하며 진행 중 가설만 수정.
- 문장 부호 없이 끝난 확정 음성은 보존·번역, 불확정 가설은 별도 기록으로 남김.
- 한국어 음성/직접 입력 → 비즈니스 영어. 단일 마이크는 회의 듣기를 멈추고 내 발언에 사용한 뒤 복귀. 탭 오디오를 사용할 때는 별도 마이크 경로.
- 의미·버전별 완료 번역 재사용, 600ms 미리보기 예약, 관련 원문 중심 문맥, 추천 1개 및 요청 시 대안 2개. 캐시를 회의 전환 시 비움.
- SSE 완료 이벤트 직후 종료, 이벤트 이름 프레이밍 지원, 타임아웃/취소 구분, 일시 오류 최대 2회 복구. 재시도 중 이전 출력 보존.
- 오프라인에서 즉시 재시도를 소진하지 않고, 온라인 복귀 시 남은 재시도 한도 내에서 실패 원문 복구.
- 가이드의 근거 없는 승인·약속 제한. 감지된 제안은 숨기고 재생성을 안내. 읽는 가이드는 유지하고 자동 생성된 새 제안은 별도 알림으로 제공.
- 회의 목적 저장, 원문 수정, Enter 변환, −/기본/+ 유지, 영역 너비 조절, 텍스트 요청 사용량 집계.

## 확인된 결과
- Node 자동 테스트 122개 통과. 빌드 및 git diff --check 통과.
- 실제 Gemini 텍스트 평가 20/20 응답 완료. 첫 토큰 중앙값 1,526ms, p95 3,424ms. API 공급자 응답 기준이며 음성 전체 지연 아님.
- 이전 16건 사전 점검 중 1건 공급자 연결 실패 발생. 이후 20건 평가에는 오류 없음. 실패 자체가 없어진다는 보장은 아님.
- EN10의 정규식 검사 실패 1건은 ‘합의한 것은 아닙니다’를 검사식 ‘않|없’이 포착하지 못한 사례. 원문 부정 의미는 보존됐음을 직접 검토. 이후 검사식에 ‘아닙’을 추가. 결과를 통역 전문가 품질 점수로 표현하지 않음.
- 가이드 초기 출력에 확인되지 않은 약속 발견. 지시문과 보수적 출력 검사 수정. 검사에서 필수 보안 검토 조건을 약속으로 오인한 경우도 수정하고 회귀 테스트 추가.
- 브라우저 실제 Google 연결 + 저장된 합성 예제 음성: 영어 원문 ‘Could you send me the meeting agenda by tomorrow?’ → ‘내일까지 회의 안건을 보내주시겠습니까?’ 완료. 한국어 ‘회의 일정을 내일 오후 3시로 변경해 주세요.’ → ‘Please reschedule the meeting to 3 PM tomorrow.’ 완료.
- 영어 예제 원문 화면 갱신 11회. 음성 연결 시작부터 첫 원문까지 2,711ms, 첫 번역까지 6,299ms (연결·음성 재생 시간 포함). 1초 목표 달성으로 주장하지 않음.
- 실제 브라우저 IndexedDB에서 2,000개 기록 저장·재읽기, 첫/마지막 문장·발언·가이드 보존. 기존 마이그레이션 원본 보존.
- 30분 상당 1,800개 문장 가속 이벤트 테스트: 확정 문장·ID 누락/중복 없음. 실제 30분 오디오 세션과 다름.
- 인앱 브라우저 390/768/1440px 화면 가로 넘침 없음, 원문 기본 글자 14px 동일, 모바일 발언 입력·마이크 버튼 접근 확인.

## 아직 검증되지 않은 범위
- 실제 마이크, 상대방 탭 음성과 내 마이크 동시 사용의 현장 음향/에코, 실제 30분 회의, 실제 휴대폰 키보드·백그라운드 복귀.
- Chrome 확장 도구는 localhost 접근이 정책상 차단됨. Edge는 제어 가능한 브라우저 목록에 없음. 인앱 Chromium 검증을 Chrome/Edge 실기기 검증이라고 표현하지 않음.
- 텍스트 생성 토큰 30~50% 절감은 목표이며 같은 회의의 변경 전후 청구 비교는 미실시. 출력 상한/캐시 재사용 테스트 통과와 실제 총비용 절감률은 구분. 음성 비용은 현재 텍스트 집계에 포함되지 않음.
- 모바일은 기존 기록/내 발언 탭 전환을 유지. 별도 하단 입력 시트는 이번 반영 범위에서 제외.
- 문맥은 근거 원문을 선택하는 방식. 별도 AI 요약 상태 모델은 사용하지 않아 요약 호출 비용이 없음. 일반적인 쟁점 검색의 완전성을 보장하지 않음.

## 사용자가 확인할 순서
1. 새 회의 → 시작 → 마이크 허용. 영어 2~3문장을 말해 원문/번역이 각각 누적되는지 확인.
2. 한국어로 말하기 → 한국어 발언 → 내 발언 마침. 오른쪽 영어 결과와 기존 회의 듣기 복귀 확인.
3. 한국어 입력 후 Enter, 답변 가이드의 새로 제안·대안 보기 확인.
4. 회의 탭 오디오를 쓰는 PC에서는 이어폰을 사용해 상대방 오디오와 내 마이크 동시 입력을 확인.
5. 회의 종료·다시 열기, 과거 스크롤 중 새 발언, 모바일 키보드 표시 상태 확인.
