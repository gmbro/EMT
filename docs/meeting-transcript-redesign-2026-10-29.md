# 누적 통역·내 발언·연결 복구·답변 가이드 및 비용 최적화 기획

2026-10-29 수정. 최신 요청에 따라 영어와 한국어를 별도 패널로 나누는 이전 안을 대체합니다. 현재 코드와 공식 문서를 검토한 기획이며 앱 구현·배포·실제 비용 측정 결과가 아닙니다. 음성·텍스트의 Google API 전송은 기존 사용자 허용 범위를 따릅니다.

## 1. 화면과 동작

데스크톱은 왼쪽 누적 기록, 오른쪽 내 발언, 하단 답변 가이드로 구성합니다. 좌우 초기 비율은 70:30을 후보로 검증하고 조절 가능하게 합니다. 기존 − / 기본 / + 크기 설정과 날짜별 회의록을 유지합니다.

### 왼쪽: 영어 원문 바로 아래 한국어 번역

```text
10:32  We can start the pilot next month, subject to security approval.
       보안 승인을 전제로 다음 달에 시범 운영을 시작할 수 있습니다.

10:33  Could you confirm which teams will participate?
       어떤 팀이 참여하는지 확인해 주실 수 있을까요?

10:33  The first phase will include…                 인식 중
       첫 단계에는…                                번역 중
```

- 원문과 번역이 한 쌍으로 계속 쌓입니다. 큰 카드와 여백을 줄이고 여러 문장을 보여줍니다. 전체 발언을 요약으로 대체하지 않습니다.
- 긴 발언도 의미 구간으로 추가합니다. 확정한 앞부분은 유지하고 마지막 인식 중인 구간만 수정합니다. 공급자 정정이나 뒤 문맥 때문에 수정하면 해당 구간만 갱신하고 표시합니다.
- 번역이 늦어져도 원문은 먼저 보여주며 바로 아래 번역 자리를 유지합니다. 결과 도착 순서와 관계없이 발화 순서로 배치합니다.
- 중간 인식 결과는 가설입니다. 그대로 모두 누적하면 중복되므로 발화 ID·원문 버전으로 진행 중 가설과 확정 기록을 구분합니다.
- 과거 기록을 읽을 때 자동 스크롤을 멈추고 새 내용 수와 ‘실시간으로’ 버튼을 제공합니다. 장시간 기록은 범위 렌더링하고 전체 내용은 기존 브라우저 저장과 연결합니다.
- 일반 회의 채널의 한국어는 원문으로 기록합니다. 한국어라는 이유만으로 사용자의 발언이라고 판단하지 않습니다.

### 오른쪽: 한국어 음성 또는 텍스트 → 영어 발언

- ‘말하기 / 입력’을 제공합니다. 내 발언 마이크로 말하면 인식된 한국어 아래 영어가 나타납니다. 인식 오류를 고치면 해당 구간만 재번역합니다.
- 뜻·조건·입장을 유지하면서 정중하고 간결한 비즈니스 영어로 작성합니다. 승인·약속·날짜를 임의로 추가하지 않습니다. 영어 음성 재생은 이번 범위가 아닙니다.
- 텍스트는 Enter 또는 변환 버튼으로 제출하고 Shift+Enter는 줄바꿈입니다. 글자마다 API를 호출하지 않습니다. 음성은 의미 구간을 기준으로 자동 번역합니다.
- 탭 오디오와 마이크를 구분할 수 있는 환경에서는 상대방 음성을 유지하며 내 발언을 처리합니다. 단일 마이크 환경에서는 내 발언 모드를 명시적으로 켜고 종료 후 회의 듣기로 돌아갑니다. 같은 마이크 음성을 두 전사 요청에 중복 전송하지 않습니다.
- 스피커 소리가 마이크로 다시 들어오는 중복 기록도 검사합니다. 채널만으로 화자 신원을 확정하지 않습니다.
- 생성된 영어는 발언 초안입니다. 사용자가 실제 발언을 확인하거나 회의 음성에서 확인되기 전에는 합의·발언 사실로 취급하지 않습니다.

### 하단: 맥락형 답변 가이드

추천 한 개를 한국어 위·영어 아래로 표시합니다. 다른 방향의 대안 두 개는 펼칠 때 생성합니다. 읽거나 복사하는 카드를 자동 교체하지 않고 ‘새 가이드’ 표시로 갱신합니다.

모바일은 기록을 주 영역으로 두고 내 발언은 하단 시트로 엽니다. 가이드는 제목과 추천안 일부가 보이는 접이식 영역으로 배치합니다. 키보드가 입력·변환 버튼을 가리지 않는지 확인합니다. 데스크톱 3영역을 그대로 축소하지 않습니다.

## 2. 연결 중단과 결과 보존

현재 오류 문구만으로 네트워크 장애라고 확정할 수 없습니다. api/translate.js는 공급자 스트림에 완료 이벤트가 없거나 출력이 비어도 같은 오류를 내며, src/cloud-translation.mjs도 완료 이벤트를 검사합니다. 현재 수동 재시도는 기존 번역을 비웁니다.

1. 요청 ID, 발화 ID/버전, 시도 횟수, HTTP 상태, 마지막 이벤트, 완료 여부, 경과 시간으로 원인을 구분합니다. 로그에 회의 본문·음성·키를 기록하지 않습니다.
2. 타임아웃, 연결 단절, 완료 이벤트 누락, 공급자 실패, 사용자 취소, 권한·결제·한도를 분리합니다. 완료 이벤트 처리와 스트림 종료 처리를 각각 검사합니다.
3. 원문과 마지막 번역을 유지한 채 별도 버퍼로 복구합니다. 미완료 출력은 ‘일부 번역’으로 표시하고 성공으로 처리하지 않습니다.
4. 일시적 오류만 실패 구간별 최대 2회 재시도합니다. 대기 후보는 1초·3초와 작은 무작위 분산이며 429는 Retry-After를 따릅니다. 인증·결제·잘못된 입력·사용자 취소는 반복하지 않습니다.
5. 회의 ID·발화 ID·버전을 검증해 과거 응답이 최신 원문이나 다른 회의를 덮지 못하게 합니다. 동일 요청을 합치고 재시도 횟수·누적 비용을 제한합니다.
6. 최신 번역·내 발언과 복구 작업에 제한된 슬롯을 배분해 밀림을 방지합니다. 전체 회의를 재번역하지 않습니다. 네트워크 복귀 시 저장된 미번역 구간을 복구합니다.
7. 번역만 실패하고 전사가 정상이면 원문 기록은 계속합니다. 음성 연결 자체가 끊기면 별도로 표시합니다. 수신하지 못한 음성을 복구했다고 표시하지 않습니다.

구간별 ‘번역 복구 중’으로 상태를 알리고 최종 실패에서만 재시도·원문 수정 버튼을 보여줍니다. 외부 연결 실패 자체를 없애겠다는 보장 대신 기록 보존과 제한된 복구를 완료 기준으로 삼습니다.

## 3. 구체적이고 전문적인 답변 가이드

현재 프롬프트는 범위·세부 사항·조건을 묻는 질문 3개만 강제합니다. 문맥도 최근 완료 발화 4개·최대 3,000자여서 긴 회의의 앞선 쟁점이 빠질 수 있습니다.

- 최신 질문 + 관련 최근 발언 + 의제·상대방 요구·확정 사실·미결 사항·제약·사용자 입장 + 필요한 용어를 사용합니다. 사실은 원문 발화 ID에 연결합니다.
- 상황에 맞게 답변, 조건 확인, 이견 제시, 다음 단계 제안 중 의도를 고릅니다. 매번 세 가지 확인 질문을 반복하지 않습니다.
- 한두 문장으로 말하기 쉽게 작성하되 근거가 있는 대상·수치·조건을 반영합니다. 없는 동의·승인·금액·기한·권한을 만들지 않습니다. 입장이 불명확하면 비확약 답변이나 확인 질문을 제안합니다.
- 회의 목적·역할 설정은 선택 사항이며 시작의 필수 입력으로 만들지 않습니다.
- 질문 완료·의사결정 요청·쟁점 전환 때 추천 한 개를 자동 생성합니다. 초기 최소 간격 후보는 10~15초이며 단순 시간 경과만으로 호출하지 않습니다. ‘새 가이드’를 누르면 즉시 요청합니다.
- 오른쪽 내 발언과 별도로 작동하며 번역보다 낮은 우선순위로 처리합니다. 실패해도 전사·통역은 계속합니다.
- 회의 문맥 압축은 주제 변경·입력 예산 초과 때만 실행하고 해당 비용도 계산합니다. 숫자·조건·합의 여부는 압축 요약만으로 확정하지 않습니다.

가상 예시: 상대가 실제로 ‘6주 구축, 보안 승인 전제’를 말했다면:

> 6주 일정에 보안 검토 기간도 포함되는지 먼저 확인하고 싶습니다.
> Could you clarify whether the six-week timeline includes the security review?

예시의 조건을 실제 회의에 임의로 삽입하지 않습니다.

## 4. 실시간 표시와 토큰 절감

### 코드에서 확인한 중복 가능 지점

- livePreviewRunner는 100ms 대기 후 실행 가능 여부를 판단하며 진행 중 요청이 끝나면 최신 작업을 실행합니다. 초당 10회 호출한다는 뜻은 아닙니다. 다만 길어지는 원문을 반복 전달할 수 있습니다.
- draft-translator는 동일 조각 캐시를 이미 사용하지만 바뀐 조각에는 맞지 않을 수 있습니다. 최종 발화 시 캐시를 지우고 별도 확정 번역을 요청합니다.
- translationContext는 최근 완료 발화 4개의 원문과 번역을 함께 최대 3,000자 전달합니다. 글자 수와 토큰 수는 다릅니다.
- 영어 확정 번역 뒤 가이드가 예약됩니다. 예약은 합쳐지지만 의미 변화에 따른 생성은 아닙니다.
- 출력 상한 2,048토큰은 실제 청구량이 아닙니다. 사고 수준도 이미 minimal/low이므로 이를 낮추기만 하면 크게 절감된다고 주장하지 않습니다.
- 현재 코드에서 작업별 사용량 집계 경로는 확인하지 못했습니다. 실제 비용에서 각 항목이 차지하는 비중은 측정해야 합니다.

### 변경안

| 항목 | 변경 | 정확도·속도 보호 |
| --- | --- | --- |
| 화면 | 받은 원문·번역 델타를 즉시 표시 | 타자 애니메이션으로 늦추지 않음. API 호출 주기와 분리 |
| 음성 번역 | 안정된 의미 구간 제출, 불안정 꼬리는 최신 한 개로 합침 | 초기 간격 후보 400~800ms. 무정지 발화도 분할. 단어별 요청 금지 |
| 미리보기 | 최종 원문·문맥·용어가 같고 정상 완료된 결과 재사용 | 바뀐 숫자·부정·조건은 해당 구간 재번역. 미완료 결과 확정 금지 |
| 문맥 | 보통 관련 원문 1~2문장 + 필요한 용어 | 지시어·조건이 이어지면 확장. 회의 전체와 원문·번역 반복 전송 제거 |
| 내 발언 | 마이크 전사 한 번, 텍스트는 제출 시 요청 | 동일 입력 중복 제출 합치기. 수정은 버전 변경 |
| 가이드 | 의미 변화 시 추천 1개, 대안 2개는 요청 시 | 번역보다 낮은 우선순위, 읽는 카드 유지 |
| 회의 상태 | 사실·결정·미결 사항만 작게 유지 | 매 발화마다 별도 요약 호출 금지. 원문 근거 참조 |
| 출력 예산 | 길이·작업에 따른 상한, 불필요한 서문 제거 | 긴 번역을 강제로 자르지 않음. 상한 축소와 실절감 구분 |
| 재시도 | 실패 구간만 제한 복구 | 전체 재전송·무한 재시도 금지 |

캐시 키는 원문, 언어 방향, 문맥·용어집 버전, 모델·프롬프트 버전을 포함합니다. 회의별로 격리한 제한된 캐시를 사용합니다. 같은 문장이라도 다른 의미·문맥의 결과를 재사용하지 않습니다.

현재 모델을 기준선으로 두고 중복 요청부터 줄입니다. 더 저렴하거나 강력한 모델로 분기하는 것은 같은 평가에서 품질·속도·비용이 개선될 때 적용합니다. 모든 문장을 별도 AI로 재심사해 비용·지연을 늘리는 구조는 피합니다.

### API 캐싱과 음성 비용

Google 공식 문서상 Interactions API는 암시적 캐싱만 지원합니다. 현재 코드의 Gemini 3.6/3.8 Flash에 제시된 최소 입력은 4,096토큰이며 적중은 보장되지 않습니다. 짧은 번역 요청을 일부러 길게 채우지 않습니다. 고정 지시문 배치를 정리하되 중복 호출 제거가 우선입니다. 캐싱 할인과 입력량 감소는 구분합니다.

현재 store:false를 유지합니다. 대화 ID로 이전 요청을 연결하는 기능은 무상태 호출과 다릅니다. 비용 절감을 이유로 서버 저장을 자동 활성화하지 않습니다. 이 설정이 Google의 모든 데이터 보존 정책까지 없애는 것으로 설명하지 않습니다.

음성 비용과 텍스트 비용을 따로 측정합니다. 동일 음성 중복 전송부터 막습니다. 무음 전송 축소는 현재 전사 모델의 프로토콜·과금 방식 및 인식 손실을 확인한 뒤 적용합니다. 다른 Live 음성 모델의 초당 토큰 수치를 그대로 적용하지 않습니다.

## 5. 검증과 완료 기준

동일한 공개·합성 회의 샘플로 변경 전후를 비교합니다. 고객 회의 내용을 진단 로그에 남기지 않습니다.

- 음성: 입력 길이, 연결 시간, 중복 요청, 제공되는 사용량 측정.
- 텍스트: 미리보기·확정·내 발언·가이드·요약·재시도별 호출 수, 입력·출력·사고·캐시 토큰을 제공 범위에서 기록. 총량과 하위 항목 중복 합산 금지.
- 취소·실패: 사용량 응답이 없으면 미확인. 브라우저 취소를 비용 0으로 간주하지 않고 공급자 사용량·청구와 대조.
- 지연: 음성 구간 끝→첫 원문, 안정된 의미 구간→첫 번역, 최종 구간→완료, 직접 입력 제출→첫 영어, 이벤트 수신→화면 표시를 분리. 인식·구간 대기 시간과 전체 지연도 보고.

목표는 다음과 같으며 아직 달성 결과가 아닙니다.

1. 원문 이벤트 수신→표시 p95 150ms 이내. 안정된 의미 구간→첫 번역 중앙값 약 1초, p95 3초 이내. 발화 시작부터 모든 정확한 통역을 1초 안에 완료한다는 보장은 아닙니다.
2. 텍스트 생성 토큰 30~50% 절감을 초기 목표로 두되 기준선 측정 뒤 확정합니다. 음성을 포함한 전체 청구액 절감률과 다릅니다.
3. 2분 무정지 발언·30분 회의에서 공급자 확정 원문, 표시, 저장 순서를 비교합니다. 앱에서 발생한 누락·중복이 없어야 합니다. 전사 자체의 오인식은 별도 평가합니다.
4. 영어→한국어와 한국어 음성/텍스트→영어를 각각 검사합니다. 가격·계약·보안·일정·반대 의견 등 최소 20개 시나리오에서 의미, 숫자, 단위, 부정, 조건, 용어, 자연스러움을 평가합니다. 세트 내 중대한 의미 오류·근거 없는 약속은 통과 불가이며 결과를 모든 회의의 무오류 보장으로 일반화하지 않습니다.
5. 연결 차단, 완료 이벤트 누락, 타임아웃, 429, 중복 이벤트, 응답 순서 역전, 재시도 중 원문 변경, 회의 전환을 재현합니다. 재시도 예산·기존 결과 보존·미완료 표시를 확인합니다.
6. 실제 Chrome/Edge의 표시·마이크·탭 오디오를 점검합니다. 모바일은 키보드, 화면 회전, 스크롤, 권한, 백그라운드 전환을 검사합니다. 합성 입력·에뮬레이션·실기기 검증을 구분해 보고합니다.

권장 순서: 사용량·지연 기준선 → 복구·버전 관리 → 쌍 누적 UI·내 발언 음성 → 요청 중복·문맥 축소 → 가이드 → 장시간·브라우저 평가. 의미를 누락하거나 지연을 늘리는 절감안은 제외합니다.
