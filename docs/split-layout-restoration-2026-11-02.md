# 실시간 받아쓰기 2분할 복원

## 원인

- `src/main.jsx`의 기본 모드는 `transcript`였으며, 같은 값으로 번역 열과 분할선을 숨겼다. 음성 처리 모드 변경이 화면 구조까지 바꾸는 회귀였다.
- `src/maestra.css`의 760px 이하 규칙은 원문과 번역을 한 열로 쌓고 열 제목을 숨겼다.
- 날짜·상태·검색은 이전 확대 요청에 따른 데스크톱 20px / 좁은 화면 18px 설정이 남아 있었다.

## 수정

- 모든 모드에서 원문 / 한국어 번역의 좌우 2분할과 너비 조절을 유지한다. 기존 연속 문단 표시도 유지한다.
- 배포 웹 기본값은 `받아쓰기 + 번역`. 로컬 Qwen 기본값은 API 키 없이 시작 가능한 `받아쓰기만`을 유지한다.
- 받아쓰기만 사용하는 경우 오른쪽 영역의 `번역 켜기`로 이후 발화부터 번역한다. 기존 원문을 일괄 재번역하거나 추가 비용을 발생시키지는 않는다.
- 설정에 한국어 번역 켜기/끄기를 추가했다. 이미 생성된 번역은 끄더라도 표시한다.
- 날짜·상태·검색 글자 12px, 상단 높이 데스크톱 36px. 본문은 기존 기본 14px 및 11~17px 설정을 유지한다.
- 창 크기·분할 너비·보조 영역 높이 변경 시 실시간 스크롤을 유지한다. 사용자가 과거 기록을 읽으면 자동으로 아래로 이동시키지 않는다.

## 확인한 범위

- 내장 브라우저에서 합성 회의 기록 30개로 실제 UI 점검.
- 320×640, 390×844, 768×1024, 1280×720, 1440×900, 844×390: 2열 유지, 가로 넘침 없음, 하단 버튼 넘침 없음, 12px 상단 / 14px 본문, 최신 위치 유지.
- 분할선 방향키 조절, 번역 끄기/켜기, 검색 결과 없음, 가이드·내 발언 숨기기, 과거 기록 탐색 후 창 크기 변경 및 실시간 위치 복귀 확인.
- 기존 자동 테스트 153개 통과. 프로덕션 빌드 및 Windows 패키지 구조·체크섬·입력 검증·Python 구문 점검 통과.
- Windows 설치 ZIP에도 수정한 화면 소스를 포함했다.

## 확인하지 않은 범위

- Windows 실기기의 Chrome / Edge, 실제 휴대폰에서의 조작은 이번 검증에 포함하지 않았다. 화면 크기 검증은 내장 브라우저의 뷰포트 에뮬레이션이다.
- 이번 수정은 UI와 표시 상태에 한정한다. 실제 마이크의 인식·번역 지연, 장시간 연속 회의, 모델 품질을 새로 측정하지 않았다.
