# 실시간 회의 번역 단위 변경 검증

## 동작

- 회의 기록 제목 옆에서 `문단 나누기` / `다 말하고 번역하기`를 선택한다. 기본값은 문단 나누기이며, 선택은 해당 브라우저에 보관된다.
- 원문은 두 모드 모두 인식되는 즉시 누적한다. 문단별 원문 아래에 완성된 한국어 번역을 붙이고 이전 문단을 유지한다.
- 문단 나누기: 확정된 원문 3문장마다 번역한다. 화자가 알려진 경우 1문장 단위로 나눈다. 구두점이 부족한 발화는 약 25초 또는 확정 원문 1,400자를 기준으로 나눈다. 3문장보다 짧아도 3초 무음이면 번역한다. 음성 인식 확정 지연이 있어 25초는 결과 표시의 보장 시간이 아니다.
- 다 말하고 번역하기: 문장 수와 문단 시간 제한으로 중간 번역하지 않고 약 3초 무음 후 번역한다. 3초 미만의 쉼은 같은 발화로 이어진다. 공급자의 종료 신호가 없으면 확정 원문에 대해 약 300ms 안정화 시간을 추가한다. 미확정 가설은 확정을 기다리고 임의로 번역하지 않는다.
- 선택 즉시 현재 미번역 원문에도 새 규칙을 적용한다. 이미 번역한 문단은 재번역하지 않는다. 종료 시 남은 확정 원문도 번역한다.
- 한국어 발언은 기존처럼 원문만 기록한다. 내 발언 만들기의 한국어→영어 변환은 별도로 유지한다.
- 번역 경계 이전의 반복 미리보기 API 호출을 제외한다. 긴 발화는 기존 번역 분할 파이프라인을 통해 같은 기록에 누적하므로 한 API 요청의 길이 제한에 맞춘다.

## 검증

- `npm test`: 190개 통과. 새 경계 테스트 17개: 3문장, 10문장 패킷 무누락·무중복, 소수점·약어, 2.95초 쉼과 3초 무음, 발화 중 양방향 모드 전환, 알려진 화자, 25초·길이 기준, 원문 정정·철회, 늦은 확정, 종료 신호 누락 등을 포함한다.
- `npm run build`: 성공.
- 브라우저 실제 Google 음성 API 및 Gemini 번역 API: 같은 합성 영어 질문을 3회 연속 재생했다. 문단 모드는 재생 시작 9,174ms, 발화 종료 모드는 11,663ms에 번역 요청을 시작했다. 두 경우 모두 번역 1회, 미리보기 0회, 3문장 원문 및 한국어 번역 완료. 이 수치는 API 요청 시작 시점이며 첫 번역 결과의 지연이나 현장 마이크 성능을 뜻하지 않는다.
- 결과 원문: `reports/translation-pacing-2026-11-19/paragraph.txt`, `after-speech.txt`.
- 실제 앱에서 선택 즉시 활성 상태와 안내가 바뀌는 것을 확인했다. 390px 화면에서 문서 가로 넘침이 없고 두 버튼이 화면 안에 배치된다.

## 검증 범위와 한계

- Google 실서비스 경로는 합성 녹음 음원으로 검증했다. 실제 회의 마이크·소음 환경, 실제 모바일 기기, Deepgram 화자 분리와 로컬 Qwen 추론의 실시간 실행은 이번 검증에 포함하지 않았다.
- 무음은 16kHz PCM 에너지로 판단한다. 주변 소음이나 멀리 있는 마이크는 경계 시점에 영향을 줄 수 있다.
- 3초는 무음 대기 기준이다. 음성 확정·네트워크·번역 모델 처리 시간이 추가된다. 어떤 모드도 첫 번역 2초를 보장하지 않는다.
- 모델, 외부 전송 대상, API 키 접근 범위를 추가하지 않았다. 기존 보안 테스트가 통과했다.
