# 회의 웹 응답성·처리 비용 최적화

## 적용한 변경

- 입력, 설정, 음량 변화 때 긴 회의 기록 전체를 다시 그리지 않도록 기록 영역과 문단을 분리·재사용한다. 변경된 문단만 갱신하며 검색은 입력 반응과 분리하고 검색용 문자열을 재사용한다.
- 큰 기록은 최신 80개 문단부터 표시하고 이전 문단을 유휴 시간에 80개씩 추가한다. 모든 문단을 최종 표시하며 저장·검색·복사·내보내기 데이터는 전체 기록이다. 자동 따라가기와 사용자의 과거 기록 스크롤을 구분한다.
- 회의 기록 클릭 시 진행 상태와 중복 클릭 방지를 즉시 적용한다. 모바일 버튼에는 `touch-action: manipulation`을 적용했다.
- 스트리밍 갱신 시 기록 ID 인덱스를 재사용하고 값이 같은 갱신은 생략한다. 실제 원문·번역의 첫 표시에는 지연 타이머를 추가하지 않는다.
- 음성 입력 표시는 현재 UI에서 사용하는 활성/대기 임계값이 바뀔 때 즉시 갱신한다. 매 음량 표본마다 전체 앱을 갱신하지 않는다.
- IndexedDB 읽기에서 전체 기록 JSON 직렬화→재파싱을 제거했다. 기존 검증·정규화·오류 복구는 유지한다.
- 느린 저장소의 임시 저장은 진행 중 1개와 최신 대기 1개로 제한한다. 보관 시 완료를 기다리며, 기존 1.5초 주기와 이탈 복구는 유지한다.
- 정확히 같은 진행 중 번역만 네트워크 요청을 공유한다. 각 소비자의 스트림과 취소는 독립적이며 마지막 소비자가 취소하면 실제 요청을 중단한다. 문맥·용어·작업·초안 여부·시간 제한·재시도 정책이 다르면 공유하지 않는다.
- 번역 모델은 검증된 Gemini 3.5 Flash-Lite, 답변 가이드는 3.8 Flash를 유지했다. 대용량 모델 Worker/WASM 및 DOCX는 필요할 때만 로딩되는 기존 경로를 확인했다.

## 측정

최적화 전은 GitHub main `7a5f9fb`의 별도 로컬 서버, 최적화 후는 현재 작업 코드이다. 같은 브라우저·화면에서 합성 영한 문단 2,000개를 열었다. `tests/performance-browser.html`의 진단 패널로 측정했다.

| 동작 | 전 | 후 | 표본 |
|---|---:|---:|---|
| 기록 열기 첫 화면 반응 | 196ms | 50ms | 각 1회 |
| 설정 열기/닫기 중앙값 | 63ms | 24ms | 각 6회 |
| 번역 옵션 전환 중앙값 | 58.5ms | 23.5ms | 각 2회 |
| 직접 입력 반영 중앙값 | 62.5ms | 54ms | 각 2회 |

측정값은 클릭/입력 캡처부터 두 번째 requestAnimationFrame까지의 시간이다. 공인 필드 INP나 모든 기기의 성능 보장이 아니다. 같은 검사 구간의 Long Task는 12개(최대 172ms)에서 0개로 줄었다. 콜드 로드·캐시·실기기 조건을 통제한 초기 로딩 비교로 사용하지 않는다.

별도 CPU 측정: 10,000개 합성 기록의 JSON 왕복 정규화 중앙값 33.51ms → 구조화 데이터 직접 정규화 2.00ms(7회). 전체 웹 지연과 혼동하지 않는다. 진행 중 동일 요청 3개가 겹치는 회귀 테스트에서는 원격 호출 1개로 처리됨을 검증했다. 총 운영 비용 절감률을 의미하지 않는다.

## 기능 검증

- 자동 테스트 228개 통과, 프로덕션 빌드 성공.
- 실제 브라우저 IndexedDB: 기존 기록 마이그레이션 원본 보존, 재접속 후 2,000개 원문·번역·발언·가이드 복원 확인.
- 2,000개 문단 전체 표시, 자동 따라가기 하단 간격 0, PageUp으로 과거 기록 탐색, 실시간 복귀, 첫 번째 원문의 정확 검색 확인.
- JSON 파일 실제 다운로드 후 첫 ID perf-0, 마지막 ID perf-1999, 원문·번역 2,000개 포함 확인.
- 임시 회의 복구 후 보관 동작 확인.
- 실제 Google 음성 + 번역 API에서 영어 음원 전사·한국어 번역과 한국어 내 발언→영어 변환을 동시에 실행해 모두 완료, 대기 0, 추천 답변 2개 생성 확인. 이번 합성 음원에서 번역 요청→첫 상태 반영은 1,023ms였다.
- 390px 모바일 폭에서 문서 가로 넘침이 없고 두 번역 옵션이 화면 안에 배치됨을 확인했다. 공개 배포 결과는 후속 보고서에 보관한다.

## 범위와 남은 조건

현재 확인한 앱 내부 병목을 수정했다. Google/Deepgram 모델 처리, 인터넷 상태, 기기 CPU·메모리·브라우저 저장소 성능은 외부 변수다. 무제한 기록의 전체 DOM은 최종적으로 모두 표시하므로 메모리 사용 자체가 무제한으로 줄어드는 구조는 아니다. 실제 120분 회의, 물리 모바일, 실제 Edge 실행에서의 성능을 이 합성 검사로 입증하지 않는다.

보고서: `reports/web-performance-2026-11-19/`. 개발용 검사 페이지와 보고서는 프로덕션 배포에서 제외한다.
